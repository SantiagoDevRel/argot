◆ What is ERC-7730? — quick pitch ▸

Clear signing. Today a wallet shows a transaction as raw hex — you sign blind. An ERC-7730 file is a small JSON that tells the wallet how to show it in plain language: "Send 100 USDC to vitalik.eth" instead of 0xa9059cbb…

The chain: verify on Sourcify → write the descriptor → wallet shows it clearly. A contract must be verified on Sourcify before its descriptor is accepted — so Sourcify is the gateway.

Where Arkiv fits: most contracts have no descriptor because writing them is manual. Arkiv can hold auto-generated candidate descriptors and make coverage queryable — "which verified contracts still lack clear signing?" Adjacent bonus, not the core migration.

  "address": "0xdAC17F958D2ee523a2206206994597C13D831ec7" }
ON-CHAIN ~Token info — decimals / ticker (mostly derivable)
EXAMPLE — TOKEN INFO
{ "ticker": "USDT", "decimals": 6 }
LLM ⚙Display mapping — how each parameter renders (the manual part today)
EXAMPLE — WHAT THE LLM PRODUCES
"transfer(address to,uint256 value)": {
  "intent": "Send",
  "fields": [
    { "path":"value", "format":"tokenAmount" },
    { "path":"to",    "format":"addressName" } ] }
Sourcify already holds the hard inputs. The only missing piece — the display mapping — is exactly what a local LLM infers. → verified inputs (Sourcify) + local LLMs (DGX) = auto-generation at scale.
