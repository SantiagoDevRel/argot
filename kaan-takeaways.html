Sourcify CTO · Kaan Uzdogan · EIP-7730 co-author

He described an Arkiv-shaped problem

The ERC-7730 standard defines how descriptors are written — it's registry-agnostic. The registry (the actual list) moved off Ledger onto the Ethereum Foundation's GitHub, but the intention is to move it onchain and make it permissionless, with trust coming from attestations. Descriptors must come from the dapps themselves; the submission process isn't built yet. Onchain · permissionless · attestation-based · queryable = the Web3 database.

“Our intention is to move this onchain and make it permissionless. But the trust will come from attestations: Ledger can attest to some descriptors' correctness with a key… The descriptors need to come from dapps themselves. Right now it has to be a PR and needs to be reviewed. We're yet to implement a process there. … The descriptors are required to be able to clear-sign transactions.”
— Kaan, Sourcify CTO (verbatim, primary source)
What the ecosystem needs — and where Arkiv fits
  • ✓
    An onchain, permissionless home for the registry not a GitHub PR bottleneck
    Arkiv is the queryable onchain database — descriptors live as entities anyone can read and write, no gatekeeper.
  • ✓
    Attestation-based trust, baked into storage who attested what
    Arkiv stores each descriptor with its attestations as queryable attributes — “show me everything Ledger attested,” answered in one query.
  • ✓
    A submission → review → adopt pipeline “yet to implement”
    Arkiv models the lifecycle natively: a candidate draft lands unattested, the app owner reviews and adopts, then attests — nothing auto-submitted.
  • ✓
    Coverage for the existing long tail the DSL only helps new contracts
    The write-time DSL streamlines future contracts; the millions of already-verified ones still show blind hex. Arkiv-hosted candidates fill that coverage gap today.
the ask Arkiv is the queryable, permissionless, attestation-aware registry Kaan is describing — plus a candidate layer that covers the long tail the DSL won't reach.
